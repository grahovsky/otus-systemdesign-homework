# arc42 §1 — Введение и цели

## 1.1 Краткий обзор

**Bookly** — сервис онлайн-бронирования объектов размещения (аналог Booking.com):
поиск по датам/гео/фильтрам, резервирование номера, оплата, подтверждение и отмена.

- **Аудитория**: проектирование взаимодействия сервисов (протоколы, API, паттерны)
- **Пользователи**: гости, партнёры-владельцы объектов, операторы поддержки
- **Ключевой сценарий**: search → soft-hold → CreateIntent → confirm/capture → confirm inventory | compensate

## 1.2 Проблема

Монолит «всё в одном CRUD» не выдерживает типичных сложностей бронирования:

- **overbooking** при параллельных запросах на один слот;
- **оплата** с идемпотентностью и внешними webhooks;
- **отмены/возвраты** с согласованной компенсацией инвентаря и платежа;
- **пики поиска** vs редкие, но критичные записи бронирования.

Нужна декомпозиция с явным выбором sync/async протоколов и паттернов согласованности.

## 1.3 Цели

| # | Цель | Метрика / критерий |
|---|---|---|
| G1 | Не допускать overbooking при concurrent booking | inventory — единственный writer слотов; soft-hold + TTL |
| G2 | Надёжный платёжный контур | идемпотентность, корректные refund при отмене |
| G3 | Развязать поиск и запись | CQRS: Search read-model не блокирует Inventory |
| G4 | Прозрачная компенсация при сбоях | Saga с явными compensate-шагами |

## 1.4 Stakeholders

| Роль | Интерес |
|---|---|
| Гость | Быстрый поиск, гарантированное место после оплаты |
| Партнёр | Контроль аллотмента, уведомления о бронях |
| Оператор | Разбор отмен/возвратов, модерация |
| Архитектор / команда | Обоснованный микс протоколов и паттернов |
