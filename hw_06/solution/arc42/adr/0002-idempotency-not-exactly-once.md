# ADR-0002 — Идемпотентность вместо exactly-once

- **Status**: Accepted
- **Date**: 2026-09-06
- **Decision makers**: архитектор

## Context

SDK повторяет батч после таймаута, хотя сервер мог уже принять предыдущую попытку.
Exactly-once на транспорте (HTTPS + Kafka at-least-once) недостижим: клиент не знает,
достиг ли ответ таймаута до или после записи. Дубликаты исказили бы воронки,
retention и DAU/MAU, если принимать каждое повторное событие как новое.

## Decision

Идемпотентная обработка по `event_id`, а не попытка гарантировать ровно одну
доставку на транспорте:

1. Ingest API проверяет окно недавних `event_id` в Redis и отбрасывает повтор
   в пределах TTL окна.
2. Storage Writer выполняет идемпотентную вставку в ClickHouse по `event_id`
   (дедуп на стороне SoT, если повтор прошёл окно Redis или пришёл с другого
   инстанса Ingest).

За пределами TTL окна Redis редкий дубликат возможен; агрегаты funnel/retention
устойчивы к единичным дублям.

## Consequences

### Позитивные

- Ретраи SDK безопасны для аналитики без exactly-once на клиенте
- Ingest остаётся в бюджете p99 < 300 мс: проверка Redis локальна для hot path
- Второй барьер в ClickHouse закрывает гонки между инстансами Ingest

### Негативные / trade-offs

- Нужно хранить окно идентификаторов в Redis (TTL, память)
- Дубликат за пределами окна может попасть в сырые события

### Риски

- Слишком короткое окно дедупа при длинных ретраях SDK → редкие двойные события.
  TTL окна задаётся больше максимального retry-budget SDK и фиксируется в сайзинге.

## Alternatives considered

### Exactly-once на транспорте (транзакционный Kafka, синхронный ack ClickHouse)

Цена не окупается: SDK всё равно может повторить HTTP-запрос после таймаута,
а синхронная OLAP-запись ломает SLO ingest ([ADR-0001](0001-batch-insert-clickhouse.md)).

### Игнорировать дубликаты, полагаться на устойчивость агрегатов

Единичный дубль воронку не ломает, поток ретраев при сетевых таймаутах — ломает.
Без дедупа пик ретраев искажает DAU/MAU.

### Дедуп только в ClickHouse без окна Redis

ClickHouse закрывает SoT, но Ingest тогда публикует заведомые дубли в Kafka
и увеличивает нагрузку на writer без выигрыша для p99 приёма.
